# Events Sequence

Event Sequence Graphs with Feature Expressions

An Event Sequence Graph (ESG) models system behaviour: a discrete, event-based model of what a system can be observed to do from the outside. A vertex is an event, an edge says one event may follow another, and a test is a walk through the graph.

An ESG with Feature Expressions (ESG-Fx) extends it by labelling every event with a feature expression — a Boolean expression over the features of the feature diagram. That label ties behaviour directly to features, so one concise model carries the behaviour of every product in the line: an ESG-Fx is the behavioural model of a whole software product line.

Reading it. Each box carries the event name in white and its feature expression underneath in amber. A feature expression restricts its event to the products that satisfy it: soda and serveSoda are labelled Soda, so they occur only in products that have the Soda feature. A leading ! is negation, so pay and change, labelled !FreeDrinks, occur in every product without FreeDrinks. Choosing a configuration drops the events whose expression comes out false, leaving that product’s own ESG.

[ and ] are pseudo events rather than behaviour: they mark where a run may begin and end, so every test is a path from one to the other.

Definition. An ESG-Fx adds to a traditional ESG a feature diagram d and a total function μ : V ↦ B(N), labelling each event with a feature expression over the features N of d.
